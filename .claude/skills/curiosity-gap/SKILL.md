# Curiosity gap

Check or rewrite a spoken script, reel, or carousel so every line opens a loop. This is a rewrite test, not a hook mill. Do not generate a list of opening lines. Do not invent a comment keyword unless the user asked for that close.

Source of the method: Norm Skrp (Norman), field note "Curiosity gap", https://normskrp.com/curiosity-gap/, pulled 31 Aug 2026. The page does not cite George Loewenstein. Treat growth claims on that page as the author's marketing, not as a finding.

## When to use

- Someone handed a draft script, reel, or carousel and asked whether the lines hold
- A line names the payoff too early and needs a rewrite under this test
- A talking-head or on-screen text piece must keep the viewer wanting the next line

## When not to use

- Generating ten hooks, first-line variants, or a swipe file
- Writing ads, posts, or a full script from a topic with no draft in hand
- Adding a "comment this word" close unless the user asked for that close
- A form that already puts the named brand or the answer in the open (a recap that cannot hide the destination). Say the test fights that form. Do not force a mid-film unanswered loop onto it.
- Sending, posting, emailing, or pitching anyone

## Required inputs

Need all three or stop and say which is missing:

1. The draft, line by line. If there is none, ask. Do not invent the script.
2. Who is speaking and what the piece is for (personal teaching, brand recap, carousel).
3. Whether a comment-keyword close was asked for. Default is no.

## The two halves

Every line must do both. A loop is not a cliffhanger and it is not a riddle.

1. Certainty of direction. The viewer knows roughly what this is about and what kind of payoff is coming.
2. Uncertainty of destination. The specific answer is pushed as far back as the form will hold.

Pure certainty is boring. Pure uncertainty is confusing. The line between the two is the curiosity gap.

After every line, ask only this: "What does the viewer want to know next?"

- If nothing, the line is dead. Rewrite or cut it.
- If the obvious next fact, you gave away too much. Pull the answer later.
- If they are lost, add direction. Do not add more mystery.

## Five moves (only as rewrites of an existing line)

Use these on the draft. Do not spray all five into a new script.

1. Ask a question they need answered.
2. Break the sentence with an ellipsis or a comma so the thought is unfinished.
3. Promise something specific is coming (one word, one exception, one move), without naming it yet.
4. Imply the next beat, then interrupt before it lands.
5. Set up a clearly wrong answer, then deliver the right one.

## Stack test

While one loop is closing, another should already be open. A line that only pays off and then sits still fails. A line that opens a third loop before the first two have a destination fails on certainty.

Mark each line as: opens, holds, pays, or dead. A pay that does not open the next loop is a stop. A dead line is a rewrite.

## How to work a draft

1. Number the lines. Do not rewrite yet.
2. For each line, write the two halves and the "want next" answer in one sentence. Label inferences if you are guessing what a viewer would want.
3. Flag lines that name the destination too early, lines with no direction, and lines that only pay off.
4. Rewrite only the flagged lines, using the smallest of the five moves that restores both halves.
5. Run the stack test once on the new pass.
6. Stop. Do not add a comment-keyword close, a send-off, or a new CTA unless the user asked.

## Output

Return the marked draft (opens / holds / pays / dead), then the rewritten lines only. Do not output a fresh script from a topic. Do not output ten variants. If the form cannot hide the destination, say so and leave the draft unforced.

## Hard rules

- Do not present an inference as a finding. Label it.
- Do not copy the author's Christian examples, his "elite ball" keyword, or his growth numbers into someone else's piece.
- Nothing you write sends itself.
